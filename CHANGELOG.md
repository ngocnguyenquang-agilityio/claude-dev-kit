## Unreleased

- Changed: `ship pr` stops while the issue's status docs are not updated (#76). Step 4 now stops when the issue file has an unticked task line (`- [ ]` or `* [ ]`), or the index has no row for the issue or its Status cell is not `closed`: it names each missing item, tells the user to run `/dev-kit:issue finish` and prints no title or body; before, it only suggested `issue finish` and went on drafting. The two checks match the PR status guard (#75). Working rules, Git: a PR that closes an issue is opened only through `/dev-kit:issue finish`, or after its status docs are updated. New eval `ship-pr-status-docs`: a fixture branch whose `feat(#14)` commit does both tasks of issue 14, but one task is unticked and the index row says `open`; the prompt is `/dev-kit:ship pr 14` with no shell; an `llm` grader wants no PR title or body, the missing status docs named and a pointer to `issue finish`. Results with the `sonnet` judge, `--ablation none`, `--scaffold`: on the old `pr.md` 1 run, 0 of 1 (judge FAIL FAIL FAIL): the reply named the unticked task and the `open` status, said it would run `issue finish` first, then printed the title and body anyway, the #72 failure; on the new `pr.md` 3 of 3, and 3 of 3 again after review added the missing-row check. `ship-commit`: `main` 3 of 3; the branch 2 of 3 in the first lot (the failing run's reply met each point of the grader, a 64-character first line with the commands printed; the judge split 1 PASS, 2 FAIL), then 3 of 3 in a second lot, so 5 of 6 on the branch; `commit.md` is unchanged. Three runs show a direction, not a measured rate.
- Added: PR status guard hook (#75). A `PreToolUse` hook on `Bash|PowerShell` blocks `gh pr create` while the issue the PR closes is not finished: its index status in `docs/issues/README.md` is not `closed`, or its issue file still has an unticked task. The reason tells Claude to run `/dev-kit:issue finish`. The issue number is the `Closes`, `Fixes` or `Resolves #N` in the command or in the body file (`--body-file=path`, `--body-file path`, `-F path`), else the `N` in the branch's first `type(#N):` commit. It passes `Refs #N` and `Part of #N`, a PR with no issue, and a repo with no issues folder. Covered by 14 hook tests (13 for the guard, 1 for the `hooks.json` wiring), not an eval, because evals on Windows cannot run `Bash`. Limits: it only sees PRs opened through Claude; the body is scanned as raw text, so a `Closes #N` in the title counts too; `safety-guard` still asks before any `gh pr create`.

Two new evals: `grill-breakdown` (a Markdown link-checker CLI whose interview rounds are already in the prompt; an `llm` grader wants 3 or more vertical items and fails a parser/checker/reporter layer item) and `grill-small-no-breakdown` (a `--json` flag; no Proposed issues). Results with the `sonnet` judge, `--ablation none`, `--scaffold`, 3 runs each: `grill-small-no-breakdown` 3 of 3 (twice); `grill-breakdown` 2 of 3 on the final `SKILL.md` (the failing run merged heading anchors into the local-link item). History: a prompt that only said every decision was settled made `grill` ask a round in 3 of 3 runs, so the prompts now carry the earlier rounds; ending with "give me the final summary" skipped the skill in 2 of 3 runs, so the prompts name the `grill` skill; the sentence "a scope that fits one PR gets no such section" let `grill` skip the list ("The whole scope fits in one PR"), so it now reads "a scope without two such parts", and a one-item-per-part sentence took `grill-breakdown` from 1 of 3 to 2 of 3. Three runs show a direction, not a measured rate.

- Added: a kit-owned memory store (#61, roadmap item 4). Durable project facts live in topic files `docs/memory/<topic>.md`, with one line per topic (a link and when to read it) in the index `docs/memory.md`; both are committed. This repo turns native auto-memory off with `"autoMemoryEnabled": false` in `.claude/settings.json`; the kit neither sets nor checks it elsewhere, so a project without it runs both memories.

- Added: `ship` eval `ship-commit` (#55). It gives `/dev-kit:ship commit 12` and a pasted diff, and checks the reply: a `<type>(#12): <summary>` first line of at most 72 characters in the imperative mood, a body that says why, the `git add` and `git commit` commands printed in code blocks, and no claim that it ran a check or committed. - Added: context nudge (#53). Covered by 7 hook tests with a transcript-shaped fixture, not an eval, since this is hook code. The `usage` field names are not a documented contract, so a rename would turn the nudge off quietly.
- Added: stop checks (#51). With no `package.json` they run the project's `*.test.{js,mjs,cjs}` files with `node --test`, so this repo is checked now; `checks` in `.claude/kit.json` names other commands as lists of words, never shell text. All checks share `stopCheckTimeoutSeconds` (270 by default); a check that overruns is stopped with its child processes and reported to Claude, where before the 300 s hook limit ended the hook with no word. Covered by hook tests, not an eval, since this is hook code. `relatedTests` still knows only Jest and Vitest.
- Added: `guard.baseBranch`. `safety-guard` asks before `Edit`, `Write` or `MultiEdit` changes a project file on the base branch and names `/dev-kit:issue new`; `"deny"` blocks, `"off"` turns it off, and `guard.git` does not affect it. It skips files outside the project, `.claude/`, `docs/plans/` and `issuesDir`, and a repository whose base branch has no commit yet. Covered by 16 hook tests, not an eval, since evals on Windows cannot run a shell.
